\section{Empirical Evaluation}
\label{sec:evaluation}

To validate both the implementation correctness and the adversarial resilience of \textsc{Ensia}, we conducted an exhaustive independent empirical evaluation across 15 individual transformation passes and 4 composite presets (\texttt{low}, \texttt{mid}, \texttt{high}, \texttt{max}). All evaluations were executed on an isolated testbed using LLVM 21.0git on x86\_64 Linux (Kernel 6.13, Intel Xeon 2.8GHz). Workloads comprise real-world cryptographic primitives (ChaCha20, AES GF($2^8$), MurmurHash3), complex non-linear state machines (8-state DFA), a key-derivation crackme, and system call wrappers.

\subsection{Resilience Against Symbolic Execution and SMT Solvers}
We evaluated binary resilience against automated constraint solvers using \textsc{angr} v9.2.148 backed by \textsc{claripy} and Z3. A non-linear key validation crackme requiring an 8-byte symbolic token was targeted. As detailed in Table~\ref{tab:symbolic_resilience}, isolated algebraic transformations (\texttt{MBAOBF}, \texttt{CSMOBF}) impose a $2.05\times$ to $2.55\times$ solver slowdown. 

Crucially, \textsc{Ensia}'s constant encryption pass (\texttt{CONSTENC}) implements a constructor-level initialization trap: key-derivation tables are constructed inside an ELF \texttt{.init\_array} routine (\texttt{\_\_ensia\_init\_const\_sbox}). Standard symbolic execution tools that initiate simulation at the binary entrypoint (\texttt{main}) encounter uninitialized memory states, causing immediate branch divergence and solver exhaustion. When the symbolic engine is configured to execute constructor initialization, composite presets exhibit exponential path-space explosion. Under \texttt{PRESET\_MAX}, symbolic execution completely timed out ($>60$s) with zero feasible solutions discovered, driven by the non-linear interaction between chaotic state transitions and 512-bit vector bit-diffusion.

\subsection{ASM-to-IR Lifting and Memory Barrier Stripping}
De-obfuscation pipelines (e.g., McSema, RetDec) typically lift machine instructions into LLVM IR and invoke optimization pipelines (\texttt{opt -O3}) to eliminate dead code and simplify predicates. \textsc{Ensia} embeds a 3-tier anti-taint and anti-simplification engine utilizing inline memory barriers (\texttt{asm volatile("" : "+r"(val))}). 

To measure the defensive efficacy of these barriers, we subjected obfuscated bitcode to aggressive \texttt{opt -passes="default<O3>"} under two regimes:
\begin{enumerate}
    \item \textbf{Barrier-Respecting Simplification:} Simulates standard compiler semantics where memory clobbers and side-effects are preserved.
    \item \textbf{Barrier-Stripping Simplification:} Simulates an adversarial lifter that aggressively strips all inline assembly and opaque memory sinks prior to optimization.
\end{enumerate}

As presented in Table~\ref{tab:barrier_stripping}, memory barriers prevent $74.9\%$ to $87.5\%$ of synthetic instructions from being simplified away under normal compilation. When an adversary strips barriers, passes like \texttt{MBAOBF} and \texttt{VOBF} suffer $51.7\%$ and $51.4\%$ simplification degradation. However, in composite presets (\texttt{PRESET\_MID}, \texttt{PRESET\_MAX}), \textsc{Ensia} entangles barrier outputs with SSA control registers; stripping memory barriers produces undefined register uses and malformed PHI nodes, causing LLVM's verification pass to reject the lifted IR.

\subsection{Dynamic Debugging, Hooking, and Patch Resistance}
\textsc{Ensia} defends against dynamic analysis through multi-layered runtime checks:
\begin{itemize}
    \item \textbf{Direct Kernel Syscalls:} Invokes \texttt{ptrace(PTRACE\_TRACEME, 0, 1, 0)} via raw syscall \texttt{0x65} and \texttt{prctl(PR\_SET\_DUMPABLE, 0)} via \texttt{0x9D}, evading libc user-space hooks.
    \item \textbf{Timing Guardrails:} Samples \texttt{rdtsc} deltas across critical basic blocks; single-stepping under GDB triggers immediate process abortion.
    \item \textbf{Prologue CRC Scanning:} Computes in-memory digests of function entry points to detect Frida/inline hooks (\texttt{0xE9} jumps). Modifying a single prologue byte raises \texttt{SIGTRAP}.
\end{itemize}
